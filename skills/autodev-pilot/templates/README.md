# 简单开发任务 AI 自动化试点包

本试点包用于把低风险、边界清楚、可自动验证的简单开发任务，从人工反复输入提示词，转换为可审核、可追溯的 AI 辅助自动化流程。Bug 修复只是其中一种场景；已有功能小改、校验或提示优化、局部规则调整和兼容性修正也可复用这套链路。AI 可以完成需求澄清、目标测试、最小实现和分层验证；人工保留入口分流、黄灯决策、最终验收以及提交、推送和部署授权。

本包依据以下材料整理：

- `AICoding/红绿灯相关开发诀窍.html`
- `AICoding/第二次AICoding会议演示文稿.md`
- `AICoding/会议纪要/第二次沟通会议，与涛总（2026-09-03）.md`

## 文件清单

| 文件 | 用途 | 建议负责人 |
| --- | --- | --- |
| `intent.md` | 记录当前基线、目标、范围、未知项和入口风险 | 提单人起草，研发确认 |
| `spec.md` | 冻结可测试的行为规格和验收口径 | 研发起草，业务或测试确认 |
| `plan.md` | 约束代码范围、测试层级、真实链路和回退方式 | 实施研发确认 |
| `tasks.md` | 按门禁拆解 AI 可执行任务及证据产物 | AI 起草，研发确认 |
| `code-review.md` | 记录 AI 自审、人工 Code Review 和阻断项 | 评审人签署 |
| `AI执行提示词.md` | 提供端到端和分阶段可复制提示词 | 实施研发使用 |
| `人工验收清单.md` | 在提交前完成独立人工核对 | 验收人签署 |
| `JIRA定时任务提示词.md` | WorkBuddy 定时轮询 JIRA 并执行试点流程 | 试点管理员配置 |

复制整套目录到项目的 `specs/<工单号>/`，替换所有 `{{...}}` 占位符后使用。项目已有 `agents.md`、`AGENTS.md`、`docs/` 或局部规则时，先读取并以更严格的约束为准。

`JIRA定时任务提示词.md` 在所有模块中保持同一份公共流程。不要在提示词里改项目名、过滤器、状态、路径、远端、每轮上限或 push/PR 策略；这些值统一放在 Skill 的 `config/module.toml`、`config/config.local.toml`，由 `scripts/config_loader.py resolve` 注入。模块业务风险、代码地图和测试入口放在 `references/domain.md`，不能靠复制另一份提示词表达。

## 适用范围

以下任务类型均可作为候选，但必须同时满足后面的绿色条件：

- 已有功能或业务规则的小范围调整。
- Bug 修复、错误提示或校验逻辑优化。
- 转换器、兼容性、格式化或边界行为调整。
- 已确认规格内的小型接口/脚本/测试补充，且不改变外部契约。

只有同时满足下列条件的任务，才可进入绿色自动化试点：

- 任务目标有明确的当前基线、期望结果和最小场景；Bug 任务还应有稳定复现步骤。
- 能在本地或受控环境构造最小且忠于现场的自动化测试或目标行为测试。
- 改动集中在一个模块或少量明确文件，预计为最小逻辑修改。
- 不改变外部接口、数据结构、业务流程、权限模型或部署拓扑。
- 有可执行的定向测试、模块测试和全量测试命令。
- 至少能完成一种真实链路验证，例如真实文件、实际入口、本地容器或 dry-run。
- 不需要生产写操作，不接触密钥、Token、真实个人信息或未脱敏客户数据。
- 失败时可通过撤销本次小范围改动恢复，且不会造成不可逆数据影响。

以下情形不纳入绿色自动化试点：

- 需要完整新模块、大范围新功能、需求口径不清或仍需要产品决策。
- 跨服务契约、公开 API、消息格式、数据库结构或迁移脚本变更。
- 支付、收费、金额、权限、安全、隐私、幂等、事务、并发、异步、恢复点等高风险逻辑。
- 加字段、改界面、改配置中心、改部署或改基础设施。
- 只能在生产环境复现，或需要生产数据、生产写操作才能验证。
- 缺少可靠测试入口，无法证明“修改前失败、修改后通过”。
- 影响范围不明、修改面持续扩大，或需要大规模重构。

## 两套灯色不要混用

### 入口风险灯色

入口灯色决定工单走哪条流水线。

| 灯色 | 判定 | 允许 AI 做什么 | 人工动作 |
| --- | --- | --- | --- |
| 绿色 | 适用条件全部满足，无排除项 | 可按本包完成红灯/目标测试、最小修改、验证和交付报告 | 最终验收后决定是否提交 |
| 黄色 | 场景、范围、环境、业务口径或风险项仍有一项不确定 | 只读调查、建立红灯/目标测试、列出方案和影响范围；未经确认不得改实现代码 | 澄清问题、缩小范围或转人工线 |
| 红色 | 命中高风险或明确排除项 | 仅可做只读分析和证据整理；不得自主实施 | 进入传统人工流程和正式设计评审 |

任一时刻出现下列情况，绿色工单立即转黄：无法构造有效红灯、真实夹具与现场不一致、需新增范围外修改、回归出现稳定失败、真实入口未走到新逻辑、工作区存在来源不明的重叠改动。命中生产操作、敏感数据、高风险业务或不可逆变更时，立即转红。

### 执行证据灯态

执行灯态描述证据成熟度，不等同于入口风险：

- 红灯证据：实现代码修改前，同一最小测试稳定失败，且失败发生在预先写明的目标断言；对于小功能或规则新增，未实现前的目标行为测试失败也属于有效红灯。
- 黄灯状态：只有静态分析或原因猜测；测试、夹具、环境、范围或是否实施仍不确定。此时不能宣布任务已确认或完成。
- 绿灯证据：同一红灯/目标测试在最小修改后通过，原断言未弱化；定向、模块、全量测试分层通过，并完成真实入口、真实文件、容器或 dry-run 中至少一项验证。

编译失败、依赖下载失败、数据库未启动、无关超时、错误夹具或“看代码觉得有问题”都不算有效红灯。只有定向测试通过也不算生产级绿灯。

## 标准流程

1. 提单人填写 `intent.md`，研发完成入口风险灯色判定。
2. 研发和验收人确认 `spec.md`，冻结当前基线、目标和验收口径。
3. 实施研发确认 `plan.md` 中的文件边界、测试命令、真实验证和停止条件。
4. AI 按 `tasks.md` 先调查并建立红灯或目标行为测试，不修改实现代码。
5. 人工核对红灯有效性；绿色继续，黄色澄清，红色退出自动化线。
6. AI 实施与红灯或目标行为测试一一对应的最小修改，不做顺手重构。
7. AI 完成自审，人工完成 Code Review；有阻断项时退回或转黄/红。
8. 评审通过后，AI 让同一测试转绿，依次完成定向、模块、全量和真实链路验证。
9. AI 输出交付证据；人工按 `人工验收清单.md` 独立复核。
10. 只有人工明确授权后，才可提交、推送、合并或部署。

## 交付证据最低标准

每个完成的工单必须同时交付以下证据，不能只写“已完成”或“测试通过”：

| 证据 | 最低内容 |
| --- | --- |
| 入口证据 | 工单号、入口灯色、判定人、命中条件和排除项检查结果 |
| 基线/场景证据 | 最小输入、当前结果或基线、目标结果、复现步骤、来源位置 |
| 红灯/目标测试证据 | 测试名、执行命令、实现前失败摘要、预期断言、失败分类 |
| 修改证据 | 修改文件清单、关键修改说明、每处修改对应的红灯编号 |
| Code Review 证据 | AI 自审、人工评审人、评审结论、阻断项和复核记录 |
| 绿灯证据 | 同一测试通过；定向、模块、全量测试的命令、结果和时间 |
| 真实链路证据 | 实际入口、真实文件、本地容器或 dry-run 的步骤与结果 |
| 异常说明 | 本次回归、既有不稳定、环境故障分别列出，不得笼统忽略 |
| 范围证据 | 最终 diff 摘要、工作区状态、未修改项、生成产物和清理结果 |
| 人工结论 | 验收人、验收时间、通过/退回/转人工、遗留风险和后续动作 |

建议将命令输出保存为文本或 CI 链接，将截图只作为辅助线索。回归测试和可重复命令才是可长期保存的主要证据。证据中必须脱敏，不得包含账号、口令、Token、主机地址、真实客户数据或个人信息。

## 试点运行建议

- 按 2026-09-03 会议口径，首轮目标为 2026-09-30 前完成初步打样并形成可展示、可复制的闭环案例。
- 按会议口径，先从候选简单工单的约 10% 开始，流程稳定后再评估提高到 30%。
- 首轮优先选择已有成功案例、结构变化少、可本地验证的简单开发任务；Bug 修复可作为首批案例之一。
- 每周统计候选工单数、入口灯色分布、自动化完成数、转黄/转红原因、人工耗时、返工数和回归遗漏数。
- 试点价值看可验证的交付质量和返工变化，不以 AI 生成代码量作为主要指标。
- 首轮打样完成后复盘模板是否减少返工、测试是否更完整、真实入口是否得到验证，再决定扩量。

## 完成定义

只有以下条件全部满足，工单才可标记为完成：

- `intent.md`、`spec.md`、`plan.md`、`tasks.md` 的关键字段已填写并由相应人员确认。
- 入口路由仍为绿色，或黄色问题已经书面确认并重新判绿。
- 有有效红灯或目标行为基线，同一断言因最小修改转绿。
- `code-review.md` 评审结论为通过，没有未关闭的阻断项。
- 定向、模块、全量测试与真实链路验证均有可复核证据。
- 最终 diff 和工作区范围符合约定，没有未经授权的顺手修改。
- 人工验收结论为通过。
- 提交、推送、合并、部署仍按项目权限和人工授权执行。
