## 评审清单

### 范围和规格

- [ ] R01 修改目标与 `intent.md` 一致，没有擅自改变任务意图。
- [ ] R02 实现行为与已冻结的 `spec.md` 一致，未通过改规格来适配实现。
- [ ] R03 只修改 `plan.md` 批准的文件和模块，没有顺手重构、格式化或无关修改。
- [ ] R04 每处实现修改都能映射到红灯/目标测试和规格场景。
- [ ] R05 对外接口、数据结构、业务流程、权限模型和部署拓扑没有越界变化。

### 正确性和可维护性

- [ ] R06 代码解决的是已证实原因或已确认目标，不是掩盖表象。
- [ ] R07 正常、负向、边界和兼容行为符合规格；空值、单元素、多元素和特殊字符等适用边界已考虑。
- [ ] R08 错误处理、日志、错误码和提示信息准确、可操作且不泄露敏感信息。
- [ ] R09 实现与项目现有编码、异常、事务、并发和资源管理约定一致。
- [ ] R10 没有明显的安全、性能、并发、幂等或数据一致性回归。

### 测试和真实接线

- [ ] R11 测试断言表达目标语义，没有删除、跳过、弱化或扩大容差制造绿灯。
- [ ] R12 测试夹具最小且忠于现场，未把无关业务文件塞入测试。
- [ ] R13 测试覆盖足以证明修改，且每项实现修改都有回归保护。
- [ ] R14 已识别单元测试可能绕过的真实入口、配置、容器或外部语义风险。
- [ ] R15 需要外部系统语义验证时，计划中有独立的本地实测证据链。

### Diff 和交付卫生

- [ ] R16 最终 Diff 只包含本工单批准范围。
- [ ] R17 用户已有修改未被覆盖、回退或混入本次变更。
- [ ] R18 没有密钥、Token、真实个人/客户数据、临时文件或构建产物误入提交。
- [ ] R19 提交说明包含 JIRA Key、任务摘要和必要的证据索引。
