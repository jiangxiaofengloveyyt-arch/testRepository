## 入口风险路由

### 绿色条件检查

- [ ] 当前基线和目标结果明确。
- [ ] Bug 可稳定复现，或新增/调整行为有可执行的目标场景。
- [ ] 可在本地或受控环境建立自动化红灯测试或目标行为测试。
- [ ] 改动集中在一个模块或少量明确文件。
- [ ] 不改变外部接口、数据结构、业务流程、权限模型或部署拓扑。
- [ ] 有定向、模块和全量测试命令。
- [ ] 可执行至少一种真实链路验证。
- [ ] 不需要生产写操作或敏感数据。
- [ ] 改动可逆，失败可恢复。

### 红色排除项检查

- [ ] 不涉及支付、收费、金额、权限、安全、隐私、幂等、事务、并发、异步或恢复点高风险逻辑。
- [ ] 不涉及数据库结构/迁移、跨服务契约、公开 API 或消息格式变更。
- [ ] 不涉及界面结构、配置中心、部署或基础设施变更。
- [ ] 不需要完整新模块或大范围新功能设计。
- [ ] 不需要生产环境才能复现或验证。
- [ ] 影响范围已知，无大规模重构迹象。

## 成功标准

- [ ] 实现前存在一个失败于预期目标断言的有效红灯或目标行为测试。
- [ ] 修改后同一测试在不弱化断言的情况下通过。
- [ ] 定向、模块、全量测试分层通过，异常有分类说明。
- [ ] `{{真实文件/真实入口/本地容器/dry-run}}` 验证通过。
- [ ] 最终修改仅覆盖本次范围，且能映射到具体红灯或目标测试。
- [ ] 人工验收通过。

## 停止条件

出现任一情况立即停止并报告，不继续修改实现代码：

- 无法构造有效红灯或目标行为测试，或失败来自编译、夹具、依赖、环境或无关用例。
- 复现结果推翻原始假设，或需求期望存在多种解释。
- 需要修改范围外模块、契约、数据结构或高风险逻辑。
- 回归出现稳定新失败，且不能证明与本次无关。
- 真实入口未走到新逻辑，或只能通过弱化测试制造绿灯。
- 工作区出现来源不明或与本次重叠的修改。
